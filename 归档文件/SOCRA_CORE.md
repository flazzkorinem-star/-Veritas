# Socra 核心产品与 Agent 逻辑

> 调研对象：[hisocra.com](https://hisocra.com/) 的 Socra AI Tutor  
> 调研日期：2026-08-01  
> 本文只记录 Socra，不包含其他项目的需求、方案或推演。

## Socra 是什么

Socra 是一款采用苏格拉底式引导的 AI 学习工具。它不把“快速给答案”当作默认流程，而是先确定学习目标，再通过连续提问让用户解释、举例、应用和反思。系统根据每次回答调整下一步，最后把对话整理成笔记、练习、评估或其他知识产物。

它的本质可以概括成一句话：

> 一个围绕学习目标运行，能够持续评价回答并决定下一步教学动作的对话系统。

## 核心流程

```text
用户输入学习主题
  → 生成并确认学习目标
  → 选择教学策略
  → AI 提出一个问题
  → 用户回答
  → 系统评价回答
  → 决定追问、提示、降阶、升级或解释
  → 更新目标和进度
  → 继续下一轮
  → 生成学习产物
```

### 1. 确定目标

用户输入主题、当前水平和期望结果。Socra 把这些内容整理成核心目标和阶段任务。目标可以编辑、增加、删除，也可以在学习过程中调整。

后面的提问、难度和进度都围绕当前目标展开。

### 2. 选择教学策略

Socra 公开提供费曼学习、主动回忆、自适应学习、作业辅导、批判性思考、连续追问等模式。

这些模式更像同一个对话引擎上的不同策略：

- 费曼模式要求用户用简单语言解释；
- 主动回忆模式从记忆逐步走向解释和应用；
- 作业模式拆题并提供提示，让用户自己完成；
- 批判思考模式检查假设、证据和推理；
- 连续追问模式围绕定义、原因、证据和后果继续深挖。

### 3. 进行对话

AI 通常一次只推进一个问题。常见提问包括：

- 你说的这个词具体是什么意思？
- 这个结论依赖什么假设？
- 有什么证据支持它？
- 能不能举一个例子？
- 如果条件改变，结论还成立吗？
- 还有别的解释吗？

### 4. 评价回答

用户回答后，系统判断：

- 回答是否正确；
- 理解停留在记忆、解释还是应用；
- 哪些部分含糊或缺失；
- 用户是否出现误解；
- 当前目标是否已经完成；
- 下一轮应该提高还是降低难度。

Socra 还会返回分数、简短反馈和徽章。官方公开了分数区间，但没有公开完整评分规则，因此分数更适合看作即时反馈，不能确认它是严格的学习测量。

### 5. 决定下一步

下一轮不是固定追问，而是根据回答选择动作：

```text
回答充分       → 提高难度或进入下一个目标
部分正确       → 追问缺失部分
结论对但理由弱 → 要求解释推理
出现误解       → 用反例或矛盾帮助自我纠正
连续卡住       → 拆小问题、给提示或换角度
要求直接回答   → 提供解释，然后继续检查理解
```

公开界面中存在“Answer my question directly”按钮。Socra 允许用户跳出纯提问流程，但这个动作由用户主动触发。

### 6. 更新状态并生成产物

每轮对话都可能更新：

- 核心目标；
- 完成进度；
- 后续问题；
- 分数和徽章；
- 建议的新目标；
- 学习草稿。

对话结束后可以生成 Memo、Blog Post、Podcast Script、练习题、知识缺口、DOK 评估等内容。

## 核心 Agent 设计

Socra 的重点不是一段很长的系统提示词，而是把一次学习对话拆成几个职责。

### 目标规划器

把用户的模糊意图转成可执行的目标、阶段和完成条件。

### 教学策略

规定 AI 在当前模式中扮演什么角色、怎样提问、什么时候给提示，以及怎样判断学习完成。

### 回答评价器

读取用户回答，提取正确内容、知识缺口、误解和理解深度。它的输出用于决定下一步，不只是生成一句表扬。

### 动作路由器

根据评价结果选择下一步：追问、提示、换角度、降阶、升级、直接解释或结束当前目标。

### 状态更新器

把本轮结果写回目标、进度、后续问题、游戏化反馈和草稿。

### 产物生成器

在对话完成后读取整段学习过程，生成指定形式的知识产物。

把这些职责连起来，就是 Socra 的核心 Agent：

```text
目标规划器
  → 教学策略
  → 对话生成
  → 回答评价器
  → 动作路由器
  → 状态更新器
  → 下一轮对话
```

## Socra 如何处理问题与卡点

Socra 的官方说明强调，提问不是随机生成，而是根据用户当前知识依次搭建“支架”。用户出错或推理中断时，系统优先使用更小的问题、更简单的表达或承上启下的提示，帮助用户自己修复缺口；只有在用户表现出掌握后才提高难度。

官方示例中的问题通常会约束回答对象。例如渗透作用示例先问“究竟在移动的是盐、水，还是两者”，再追问水为什么向溶质更多的一侧移动。这比笼统询问“你怎么理解渗透作用”更明确：用户知道第一问只需识别移动对象，第二问需要解释原因。

可以确认：

- Socra 会优先检查用户推理，而不是直接给出完整结论；
- 回答错误时会使用较小的支架问题，而非只说“错了”；
- 支架可以表现为更小的问题、更简单的表述或桥接提示；
- 难度和下一步会随用户当前表现变化；
- 对话保持围绕明确学习目标推进。

不能确认：

- Socra 没有公开完整的问题生成提示词；
- 官方资料没有证明每个问题都明确写出回答范围、长度和评价点；
- 无法确认它是否始终能避免“你怎么理解”这类歧义问法。

因此，从公开资料可以借鉴的是“具体问题 → 识别断点 → 小步支架 → 掌握后升级”的机制，但不能假设 Socra 已经提供了一套可直接复制的问题清晰度协议。

## 公开客户端透露出的运行方式

Socra 的公开前端向 `/api/chat` 发送对话类型、消息、模型、动作和语言等信息。

服务端通过流式事件分别返回：

```text
text-delta          对话文字
gamification        分数和反馈
follow-up           后续问题
core-goals-update   目标更新
suggested-goals     建议目标
draft-update        草稿更新
artifact-created    新生成的产物
finish              本轮结束
```

这说明一次 AI 回合会产生多种结构化结果，不只是返回一段聊天文本。

它的消息也不是单纯的顺序列表。公开客户端包含父消息、子消息和当前分支，可以保留重新生成后产生的不同对话路径。

## UI 结构

应用内部采用工具型双栏布局：

```text
左侧：学习对话
右侧：Workspace
```

Workspace 显示核心目标、完成进度、分数和徽章。对话区底部提供模型选择、语音输入、直接回答和生成产物等操作。

它的 UI 重点是让用户同时看到“正在聊什么”和“这次学习进行到哪里”。

## 可以确认和不能确认的部分

已经可以确认：

- 目标先于正式对话；
- 不同模式共享基础对话能力；
- 每轮可以同时更新文本、目标、反馈和产物；
- 回答后会进行评价并调整下一步；
- 对话支持分支；
- 对话可以转成知识产物。

公开资料无法确认：

- 完整系统提示词；
- 服务端具体调用了几次模型；
- 回答评价和对话生成是否使用同一个模型；
- 分数的完整计算规则；
- 跨会话薄弱点记忆是否已经稳定上线；
- 服务端模型路由和数据保存细节。
