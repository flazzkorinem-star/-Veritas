# 历史验收摘要

这里记录以前做过、但不必每天重跑的验证结果。日常开发仍以自动化测试为准。

## 真实材料与容量

2026 年 8 月，六份 PDF、DOCX 和 PPTX 在本地生产 Edge 中走通上传、知识地图、首问、教学对话、主题完成和报告。上传到首问耗时为 12.7—89.0 秒，过程中没有未处理的浏览器或接口错误。

一份约 5 MB、28 万中文字符的 DOCX 在 72.5 秒内完成完整知识地图和首问，低于文本型材料 180 秒的目标上界。这是容量链路的可行性验证，不应写成统计意义上的 P95 承诺。

## 诊断回归

一次 120 次会话的前后版本对比得到以下结果：

| 问题                         |  修复前 |  修复后 |
| ---------------------------- | ------: | ------: |
| 首问符合记忆层目标           | 22 / 62 | 62 / 62 |
| 不完整回答被错误放行         | 12 / 37 |  1 / 20 |
| 正确推进后出现第二道正式问题 | 31 / 37 |  2 / 20 |
| 连续三次“不会”后自动讲解     |   0 / 3 |   3 / 3 |

四个直接缺陷都有明显改善，但整体稳定性没有同步变好。严格 PASS 率从 56.7% 变为 58.3%，同时曾出现非回答消息污染诊断状态和用户可见重试。后续修复应以当前自动化测试和新的真实回归为准，不把这些历史百分比当作永久基线。

## 原始记录

历史评测的原始 JSON、截图、完整对话和报告不再放在主工作树中。它们体积大、含重复内容，也会让新开发者误以为项目需要维护一套研究平台。需要追溯时使用 Git 历史；当前仓库只保留可运行测试、必要夹具和本摘要。
