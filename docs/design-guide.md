# Veritas 产品设计文档 v3.3

> 本文档是 Veritas 的产品真相源。后续代码、Agent prompt、UI 和文档更新都以本文档为准。
> 最后更新：2026-07-28

## 1. 产品定位

Veritas 是材料驱动的「诊断驱动学习」工具。
用户上传材料后，Veritas 抽取值得检测的知识节点，通过分层追问诊断用户哪里真懂、哪里没懂，再用苏格拉底式追问与引导帮用户把没懂的补上，并生成引用用户原话的诊断报告。

诊断是手段，学会才是目的：先用检测精准定位盲点，再围绕盲点引导用户真正学会，不止于打分让人走。

核心价值：
- 材料驱动：诊断对象只来自用户上传材料。
- 系统主动：用户不需要自己出题，系统主动开始诊断。
- 分层追问：值得检测的知识节点统一按记忆→理解→应用→分析推进。
- 诊断驱动学习：检测发现盲点后，用苏格拉底式追问与引导帮用户真正学会。
- 有据可查：报告引用用户原话，指出具体盲点。

## 2. 目标用户

完成或正在学习材料、想验证并补齐理解的人。
典型场景：面试备考、考试复习、资格认证、查漏补缺。

## 3. 核心流程

上传材料（可一次传多份，存进材料库）  
→ Agent 1 抽取 1–15 个值得检测的知识节点，并标注重要度  
→ Agent 2 逐节点四层诊断（记忆→理解→应用→分析），没懂就引导学会  
→ Agent 3 生成诊断报告

## 4. 输入与材料边界

当前支持上传格式：PDF、DOCX、PPTX、TXT、Markdown

材料边界：
- 诊断只考材料中出现或明确暗示的概念，不引入材料以外的知识点作为考察对象。
- Agent 可以用通用知识判断用户回答是否正确，也可以构造类比或场景辅助追问，但考察对象始终限于材料内容。

## 5. 知识节点

Agent 1（节点分析师）从材料抽取值得检测的知识节点，按重要度分级，不做泛泛总结。

输入：材料可读文本
输出：1–15 个知识节点，每个节点包含：稳定 id、节点名称、一句话说明、材料证据片段、重要度、优先级理由

入选门槛（先过门槛，再分级）：
- 只有"值得检测"的知识点才入选：要能支撑记忆→理解→应用→分析四层追问、有诊断价值。
- 犄角旮旯、纯背景描述、无法追问的孤立事实、诊断价值低的细节一律不入选。

优先选择：
- 核心概念和定义
- 容易混淆的对比点
- 能迁移到场景应用的问题
- 容易暴露推理断点的机制或因果链

重要度分级（只在已入选节点之间分高低，不设文字等级名）：
- 三档相对排序，用视觉强弱表达（如图标数量、颜色深浅）。所有入选节点本身已经是"值得检测"的。
- 重要度是给用户的学习引导和排序建议，不是能否检测的门禁——每个节点都能进四层诊断，用户可自行调整 AI 给出的重要度排序。

节点规则：
- 1–15 个，按重要度从高到低排序，宁少勿滥；材料少就少抽，不凑数；信息密度极大时也只保留最值得检测的，不超过15个。
- 每个节点都要能支撑记忆、理解、应用、分析四层追问。
- 每个节点是独立诊断单元。
- 界面引导用户从最重要往下学，但用户可自行调整任一节点的重要度、自选从哪个节点开始（AI 判断的重要度未必等于用户自己的重要线）。
- 若材料过于单薄、抽不出有效节点，提示用户补充或更换材料，不强行开始诊断。

## 6. 认知层级与推进

| 层级 | 通过标准 |
|------|----------|
| 记忆 | 能识别概念或说出基本定义 |
| 理解 | 能用自己的话解释，不只是复述原文 |
| 应用 | 能把概念放进具体场景并说明怎么用 |
| 分析 | 能拆出机制、因果、边界或对比关系 |

不算通过：只堆关键词、答非所问、逻辑矛盾、场景应用和概念无关、看答案后才答对。

每个节点固定走四层：记忆→理解→应用→分析，四层全部完成后进入下一节点。

层级是唯一推进依据，不设固定轮次：通过当前层级才进入下一层；未通过就继续围绕当前层级对话，不为走完层级强行推进。只有用户在回答当前知识问题时，Agent 2 才判断当前层级是否通过；如果用户说了别的，也需要正常回应，再自然拉回当前知识点。

## 7. 提示、答案与评分

界面常驻两个按钮：给我提示 / 给我答案

- 给我提示：提供切入点、思考方向、线索或类比，不直接替用户回答。使用提示后答对，仍算通过。
- 给我答案：给出当前问题的完整答案，将当前层级标记为“答案辅助”后进入下一层，该层不算独立通过。

提示和答案的使用记录只由用户点击按钮触发，由代码记录；Agent 在对话中主动给的类比或思路不计入提示使用。报告记录提示和答案的使用情况。设计上鼓励使用提示，不鼓励直接看答案。

评分：分数是辅助摘要，不是核心结论；核心是层级通过情况、盲点证据和下一步建议。

每个节点独立计分，满分 100，四层各 25 分：
- 独立通过：25 分
- 提示后通过：25 分（提示不扣分，只在报告标注用过提示）
- 答案辅助：0 分，并在报告中标记

## 8. 对话与诊断

Agent 2（知识检验家教）逐节点完成分层诊断。

输入：当前节点、材料证据、当前层级、对话历史、用户回答
输出：自然对话回复 + 结构化状态

结构化状态包含：
- 当前层级是否通过（语义判断）
- 当前盲点摘要

下一步动作（继续当前层 / 进入下一层 / 完成节点）和提示、答案的使用记录属于确定性状态，由代码维护，不由 Agent 2 上报。

定位：一个像真人一样对话的家教，先检验用户是否真正理解当前知识点，再帮没懂的用户学会。用户理解了就真诚鼓励；没理解就用苏格拉底式追问引导——通过追问、反馈、换角度、给类比、给思路等方法帮他自己想明白，而不是直接灌答案。检验是为了找到该教什么，教会才是目的。

对话原则：
- 主线永远是检验并引导学会当前知识点，不主动开辟闲聊、情绪、产品体验等支线。
- 用户难免说题外话（闲聊、想被夸、吐槽、走神等），需要像朋友一般自然承接几句，再把话题拉回当前知识点。既不无视，也不扯远。
- 只在用户真的在回答当前知识问题时，才判断该层是否通过。
- 每轮用 1–3 个短句，只推进一个范围明确、容易开口的问题；节点第一问尤其要低门槛。
- 必要时提供不泄露结论的回答抓手，并根据用户实际回答自然反馈。
- 怎么说话有充分自由，只受"完成当前节点的检验与学会"这个目标约束：可以自由地夸、自由地举例、自由地接话，但始终服务于这个目标。
- 像人一样靠常识灵活应对，不照脚本走、不套固定话术、不为每种情况预设台词或禁令。不把结构化状态播报给用户。

## 9. 诊断报告

Agent 3（报告生成器）在所有节点完成后自动生成诊断报告，不提前生成。报告生成后对话仍可继续，但不需要更新报告。

输入：所有节点的对话、层级状态、提示/答案记录、用户原话、材料证据
输出：个人化诊断报告

报告顶部：
- 各节点得分（每节点满分 100）
- 各层级通过情况
- 主要盲点摘要

每个节点：
- 层级通过情况
- 用户原话证据（引用真实原话，不编造）
- 具体盲点
- 是否使用提示、答案
- 正确理解
- 下一步建议

展示规则：节点条目默认折叠，优先展开最需要关注的 1-2 个。

语气要求：具体、直接、可执行。说清楚用户卡在哪里，不说"需要加强理解"这类空话。

## 10. 主界面

进入应用先到书架首页（材料库），选一份材料后进入四栏诊断工作台。

呈现原则：AI 对材料的内部分析结果（分类、排序、统计），通过渐进式的视觉呈现传达给用户。

### 书架首页（材料库）
- 每份上传过的材料是一张卡片：材料名、知识点数、诊断进度（未开始 / 进行中 x/总 / 已完成）
- 支持一次上传多份材料存进材料库，下次直接从库里选，不必重复上传
- 上传解析期间显示当前文件、已处理份数和进度条，进度条在解析期间持续呈现动态反馈
- 点卡片进入该材料的诊断工作台
- 卡片三点菜单：置顶 / 取消置顶、重命名、分享（置灰）、删除；重命名使用页面内弹窗

### 四栏诊断工作台
[ 左侧工作区 ] [ 知识地图 ] [ 对话区 ] [ 右侧诊断旁注栏 ]

左侧工作区
- 返回书架、新建诊断、本地报告、设置入口
- 显示材料列表用于切换，不使用“最近 / 本地历史”命名，不显示材料下的知识点
- 材料列表支持置顶 / 取消置顶、重命名、分享（置灰）、删除；重命名使用页面内弹窗

知识地图（取代原知识点栏）
- 上传材料解析后自动填充，节点按重要度分组，用视觉强弱区分组别（不用文字等级名），组内按建议顺序排列
- 默认只展开最优先一组，其余组收起；用户可手动展开查看
- 界面引导从最优先组往下学，但用户可点任意节点作为起点
- 点击节点切换到该节点的独立对话，并显示该节点的诊断状态
- 节点行提供三点菜单：调整重要度、置顶 / 取消置顶、重命名、分享（置灰）、删除；调整重要度使用页面内弹窗三档直选并标出当前档，重命名也使用页面内弹窗

对话区
- 只承载当前对话，不塞进度和报告信息
- 上传解析完成后 Agent 先发轻量诊断计划（知识点数量、建议顺序），再衔接第一个问题
- 底部提供：输入框、语音输入、给我提示、给我答案

右侧诊断旁注栏
- 当前分数、当前知识节点、知识地图概览、当前层级
- 层级状态：已通过、进行中、未通过、答案辅助、未开始
- 看过答案后继续推进标记为答案辅助，不算独立通过也不算未通过
- 只放当前决策需要的信息，不做信息堆叠

## 11. 本地保存

当前阶段只做本地保存。

保存内容：
- 材料库（上传过的材料，可复用，不必重传）
- 本地诊断历史
- 知识节点与重要度
- 对话记录
- 层级状态
- 诊断报告

实现可以从 localStorage 或 IndexedDB 起步。由于单条诊断包含材料文本、节点、独立对话、层级状态和报告，优先考虑 IndexedDB。用户应知道这些数据只保存在当前浏览器。持久化结构应有 schema 版本和迁移入口；只保存跨会话需要恢复的诊断状态，不保存错误提示、进行中请求或当前 Agent 临时响应等运行态字段。

## 12. 成功标准

一次完整诊断应该做到：
- 对话像和家教真实交流，而不是机械考试；用户卡住时系统用苏格拉底式追问引导他想明白。
- 报告引用用户原话，指出具体盲点；分数能看，但不盖过诊断证据。

如果用户在 Veritas 上不仅明确知道"我到底哪里没懂"，还在引导下把没懂的真正学会了，Veritas 就完成了核心任务。
