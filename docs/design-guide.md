# Veritas 产品设计文档 v3.0

> 本文档是 Veritas 的产品真相源。后续代码、Agent prompt、UI 和文档更新都以本文档为准。
> 最后更新：2026-05-28

## 1. 产品定位

Veritas 是面向备考和面试场景的 AI 理解诊断工具。

它不替用户学习完整课程，也不做通用答疑。用户只需要上传材料，Veritas 会主动识别高价值知识节点，通过分层追问暴露理解盲点，最后生成基于用户原话的诊断报告。

核心价值：

- 用户不需要知道自己哪里不懂，也不需要知道材料里的重点是什么，Veritas 替用户找问题。
- 诊断基于用户自己的材料，不考无关知识。
- 报告基于用户原话，不给空泛评价。
- 分数只是辅助摘要，真正重要的是层级通过情况和盲点证据。

## 2. 目标用户

优先服务有外部压力、需要确认自己是否真的理解知识的人：

- 面试备考者：担心被追问到不会解释。
- 考试复习者：背过材料，但不确定能否应用。
- 培训或资格认证学习者：需要知道自己哪些概念还不清楚。

暂不面向泛学习陪伴、知识社区、长期课程学习或娱乐化学习。

## 3. 核心流程

```text
上传材料
  -> Agent 1 抽取高诊断价值知识节点
  -> 展示知识点导航
  -> 用户选择节点或按顺序开始
  -> Agent 2 分层追问
  -> 完成快速路径后选择：完成 / 深入
  -> 所有目标节点完成
  -> Agent 3 生成诊断报告
```

主流程保持简单：上传材料、对话诊断、报告复盘。

## 4. 输入与材料边界

当前支持文件上传：

- PDF
- DOCX
- PPTX
- TXT
- Markdown

V1 不做账号、云端文件库、扫描件 OCR、图片图表识别或真实 RAG。文件中无法提取到的内容，不作为诊断依据。

材料边界：

- Agent 可以使用通用知识帮助判断概念理解，但问题必须围绕材料中出现或明确暗示的概念。
- Agent 可以自行构造场景和类比来推进高层级追问，但场景必须服务于材料中出现的概念，不引入材料完全没有涉及的额外知识点作为考察对象。
- 如果材料本身疑似包含错误，报告可以提示“材料表述可能存在问题”，但不要把 Veritas 变成资料校对工具。

## 5. 知识节点

Agent 1 的任务不是泛泛总结材料，而是抽取最值得诊断的知识节点。

优先选择：

- 核心概念和定义。
- 容易混淆的对比点。
- 能迁移到场景应用的问题。
- 容易暴露推理断点的机制、因果链或决策点。

避免选择：

- 纯背景描述。
- 无法追问的孤立事实。
- 过细、过窄、对理解诊断价值低的内容。

上传后，系统应把知识节点像目录一样展示出来。用户可以选择从某个节点开始，系统也应引导用户按顺序完成。

每个知识节点是独立诊断单元。

单次诊断最多 8 个节点。材料太多时，Agent 1 按诊断价值排序选前 8 个，并提示用户“还有更多内容，可以分批上传”。

材料太少时，Agent 1 不为了凑数量而降低节点质量。能抽出几个高价值节点就是几个，哪怕只有 1 个也正常，界面提示“这份材料识别到 X 个核心节点”。

## 6. 认知层级

Veritas 内部使用六个递进层级：

1. 记忆：能识别或回忆基本概念。
2. 理解：能用自己的话解释概念。
3. 应用：能在具体场景中使用概念。
4. 分析：能拆解机制、边界、因果或对比。
5. 评价：能判断方案、权衡取舍或指出风险。
6. 创造：能提出新方案、变式或迁移设计。

最低通过标准：

- 记忆：能识别概念或说出基本定义。
- 理解：能用自己的话解释，不只是复述材料原文。
- 应用：能把概念放进具体场景，并说明怎么用。
- 分析：能拆出机制、因果、边界或对比关系。
- 评价：能做判断和取舍，并说出理由。
- 创造：能提出新方案、变式或迁移用法，且和概念逻辑一致。

以下情况不能算通过：只堆关键词、答非所问、逻辑矛盾、场景应用和概念无关、看答案后才答对。

## 7. 快速路径与深入路径

每个知识节点默认先走快速路径：

```text
记忆 -> 理解 -> 应用
```

快速路径完成后，用户有两个选择：

- 完成：进入下一个知识节点。
- 深入：继续当前知识节点，进入分析和评价层。

深入路径是快速路径的延伸，不是独立入口。用户必须先完成 1-3 层，才能进入 4-6 层。

深入路径重点覆盖：

```text
分析 -> 评价
```

创造层不进入当前 V1 自动诊断主流程。Agent 1 仍可标记某个知识节点具备创造层潜力，但 Agent 2 当前只自动推进到分析和评价层。后续如开放创造层，应通过显式入口进入，不在评价通过后自动进入。

Agent 1 的适用层级是上限。Agent 1 标记某层不适用，Agent 2 不进入该层；Agent 1 标记创造层适用，只代表该节点具备后续开放创造层的资格，不代表当前 V1 自动进入创造层。

## 8. 推进规则

层级是唯一推进依据，不设置固定轮次。

Agent 2 应像带着知识检验目标的家教，根据对话实际状态自主判断推进方式。学生说什么都先正常回应，再自然回到当前知识点。主线始终是知识检验，不额外开辟陪聊或闲聊流程，也不按固定场景模板套话术。

只有学生真的在回答当前知识问题时，Agent 2 才判断当前层级是否通过。通过当前层级才进入下一层；没有通过就继续围绕当前层级对话。不要为了走完层级而强行追问。某个节点不适合高层级时，应停在合理位置。

## 9. 提示与答案

界面常驻两个按钮：

- 给我提示
- 给我答案

“给我提示”表示用户主动求助。提示应提供关键切入点、思考方向或结构化线索，不直接替用户完成回答。

“给我答案”会触发一次正常对话，让 Agent 给出当前问题的答案。用户看过答案后，可以继续问一个类似问题，也可以跳到下一层级；该层级不计为独立通过。

提示和答案都由 Agent 2 根据当前层级、当前问题、最近回答和材料证据动态生成，不做预生成。用户点击“给我提示”或“给我答案”时，先在对话区显示同名用户气泡，再显示 Agent 回复。同一层级、同一问题下生成过的提示可以缓存复用。

Agent 主动给类比和用户点击提示不同：

- 主动类比：Agent 在对话中自然换角度引导。
- 提示按钮：用户明确要求一个线索。
- 答案按钮：用户明确放弃独立作答，要求看答案。

报告必须记录提示和答案的使用情况。

## 10. Agent 职责

### Agent 1：节点分析师

输入：用户上传材料的可读文本。

输出：高诊断价值知识节点列表。

职责：

- 识别材料中最值得诊断的节点。
- 给出节点名称、一句话说明、材料证据片段、适用层级和优先级理由。
- 优先选择能支撑理解、应用和分析的问题。

不做：

- 不生成对话问题。
- 不评价用户。
- 不扩展成课程大纲。

输出给后续流程的最小结构：

- 节点名称
- 一句话说明
- 材料证据片段
- 适用层级
- 优先级理由

### Agent 2：知识检验家教

输入：当前知识节点、材料证据、当前层级、对话历史和用户回答。

输出：自然对话回复，并给出结构化状态。

职责：

- 像带着知识检验目标的家教一样和用户对话，在聊天中确认理解。
- 判断用户是否通过当前层级。
- 根据回答质量自然追问、反馈、换角度、给类比或推进。
- 在用户没有理解时提供有限脚手架。

风格：

- 不是考官，不要冷冰冰出题。
- 回应简洁，只说当前问题相关内容。
- 先正常回应用户的话，再判断是否说清楚；不要把结构化状态直接播报给用户。
- 用户答对要有反应，答错要有判断。
- 不按固定场景模板套话术；对话不顺时，先修复理解关系，再继续围绕当前知识点推进。
- 不延伸无关知识点，不主动讲整堂课。

Agent 2 的结构化状态至少应表达：

- 对用户展示的自然回复。
- 当前层级。
- 当前层级是否通过。
- 下一步是继续当前层、进入下一层、完成节点，还是进入深入选择。
- 是否使用了提示、答案或主动类比。
- 当前暴露出的盲点摘要。

### Agent 3：诊断报告生成器

输入：所有节点的对话、层级状态、提示/答案记录、用户原话和材料证据。

输出：个人化诊断报告。

职责：

- 总结每个节点的层级通过情况。
- 精准指出用户在哪个概念上有盲点。
- 引用用户真实原话作为证据。
- 说明是否借助提示、答案或类比才通过。
- 给出正确理解和下一步怎么补。

不做：

- 不生成泛泛学习鸡汤。
- 不编造用户没有说过的话。
- 不把分数当成核心结论。

最简报告模板：

```text
总分：X / 100
快速路径：记忆 ✅ / 理解 ✅ / 应用 ❌
主要盲点：一句话说明

节点：节点名称
通过情况：记忆通过，理解提示后通过，应用未通过
证据：用户说过「……」
诊断：用户卡在哪里，为什么没有通过对应层级
正确理解：针对该盲点给出简洁解释
下一步怎么补：一个可执行建议
```

## 11. 评分

Veritas 保留 0-100 分，但分数只是辅助摘要。

快速路径三层计分：

- 记忆层通过：33 分
- 理解层通过：33 分
- 应用层通过：34 分

总分 = 三层得分相加。

深入路径不参与基础分数，而是单独展示层级状态：

- 分析：通过 / 未通过 / 未尝试
- 评价：通过 / 未通过 / 未尝试
- 创造：通过 / 未通过 / 不适用 / 未尝试

提示和答案对分数的影响：

- 独立通过：拿该层分数。
- 提示后通过：拿该层分数，但报告标记“提示后通过”。
- Agent 主动类比后通过：拿该层分数，但报告标记“换角度引导后通过”。
- 看答案后通过：不拿该层分数，报告标记“需要答案辅助”。

报告的核心不是分数，而是层级通过情况、盲点证据和下一步建议。

## 12. 诊断报告

正式诊断报告按“上传材料 / 诊断记录”生成一份，不按单个知识点生成正式报告。知识点可以有阶段性小结，但正式报告必须回答用户对整份材料的掌握情况。

报告不应在少量问答后随时生成。所有必做知识点完成快速路径后，系统自动生成正式报告；未完成前只展示当前进度。报告生成后不锁定对话，用户继续对话时，已有报告保留但标记为需要更新。工程状态上，报告已生成但仍可继续对话的阶段应与普通诊断中阶段区分，避免把报告终态和对话推进混在同一个状态里。

报告顶部展示：

- 总分 0-100
- 快速路径通过情况
- 深入路径完成情况
- 最主要的盲点摘要

每个知识节点展示：

- 节点名称
- 层级通过情况
- 用户原话证据
- 暴露出的具体盲点
- 是否使用提示、答案或类比
- 正确理解
- 下一步怎么补

报告展示默认保持摘要化：顶部给文件级结论，知识点条目默认折叠，只优先展开最需要关注的 1-2 个知识点，避免把所有轮次问答平铺成流水账。

报告语气要具体、直接、可执行。不要只说“需要加强理解”，而要说明用户到底卡在哪里。

## 13. 主界面

核心界面是三栏诊断工作台：

```text
[ 左侧工作区 ] [ 中间对话区 ] [ 右侧诊断面板 ]
```

左侧工作区：

- 新建诊断
- 本地历史
- 本地报告
- 设置入口

当前先做本地保存，不做账号和云同步。

第一版三栏工作台做当前诊断和 IndexedDB 本地历史；左侧“最近”显示诊断记录，不显示该记录下的知识点；一条上传材料对应一条诊断记录，记录内包含多个知识点和各自对话；不做材料库或成就入口。材料库等能力等核心诊断体验稳定后再考虑。

左侧诊断记录和中间知识点行都提供三点更多菜单。菜单顺序为：置顶 / 取消置顶、重命名、分享、删除。当前阶段分享只置灰展示，不实现公开分享或链接能力。

中间对话区：

- 像即时通讯工具一样清爽。
- 只承载用户和 AI 的当前对话。
- 不塞大段说明、复杂进度和报告信息。
- 底部提供输入框、语音输入、给我提示、给我答案。
- 用户发送普通回答后，用户气泡应立即出现在对话区，不等待 Agent 回复完成。
- 桌面端第一版在中间区左侧内嵌约 220px 的知识点列表；上传材料并提取节点后自动填充，点击节点切换到该节点的独立对话。
- 上传材料解析完成后，Agent 先在对话区发出一条轻量诊断计划，说明识别到的知识点数量、建议顺序和快速路径，再衔接第一个问题。

右侧诊断面板：

- 当前分数
- 当前知识节点
- 知识节点列表
- 当前层级
- 快速路径和深入路径状态
- 层级状态要区分已通过、进行中、未通过、答案辅助、未开始和不适用；不适用要弱化显示，不占用和未开始同等注意力。看过答案后继续推进的层级应标记为答案辅助，而不是未通过或独立通过。

右侧面板只放当前决策需要的信息，不做信息堆叠。

移动端可以优先展示中间对话区，左右栏以后再做抽屉或折叠面板。

第一版桌面优先，暂不做移动端适配。无材料时可以上传文件或粘贴材料文本开始诊断，但不能把 Veritas 当成无材料的通用问答工具。

## 14. 本地保存

当前阶段只做本地保存，暂不上账号系统。

保存内容：

- 本地诊断历史
- 知识节点
- 对话记录
- 层级状态
- 诊断报告

实现可以从 localStorage 或 IndexedDB 起步。由于单条诊断包含材料文本、节点、独立对话、层级状态和报告，优先考虑 IndexedDB。用户应知道这些数据只保存在当前浏览器。持久化结构应有 schema 版本和迁移入口；只保存跨会话需要恢复的诊断状态，不保存错误提示、进行中请求或当前 Agent 临时响应等运行态字段。

不做：

- 账号登录
- 云端同步
- 多设备历史
- 分享链接
- 权限系统

## 15. 当前不做

为了保持产品简单，当前阶段不做：

- 账号系统
- 云端保存
- 社区
- 公开分享
- 完整课程学习路径
- 选择题主流程
- 游戏化系统
- 复杂知识图谱
- 真实 RAG
- OCR 和图片理解
- 多人协作

这些功能只有在核心诊断体验跑顺后再考虑。

## 16. 工程原则

- 保持三 Agent 架构，但允许 Agent 2 从“提问器”升级为“诊断对话者”。
- 确定性状态由代码维护，语义判断交给 Agent。
- 不用固定轮次模拟理解，层级通过才是推进依据。
- Prompt、状态结构和 UI 必须围绕层级诊断设计。
- 优先把核心体验跑顺，不做提前扩展。

## 17. 成功标准

一次完整诊断应该做到：

- 用户上传材料后，能看到清楚的知识节点目录。
- 用户不需要自己提出问题，系统会主动开始诊断。
- 对话像真实交流，而不是机械考试。
- 用户卡住时，系统会换角度引导，而不是无限重复问题。
- 报告能引用用户原话，指出具体盲点。
- 分数能看，但不会盖过诊断证据。

如果用户看完报告后能明确知道“我到底哪里没懂、下一步该补什么”，Veritas 就完成了核心任务。
