# Veritas 产品设计文档 v3.2

> 本文档是 Veritas 的产品真相源。后续代码、Agent prompt、UI 和文档更新都以本文档为准。
> 最后更新：2026-05-29

## 1. 产品定位

Veritas 是材料驱动的 AI 理解诊断工具。
用户上传材料后，Veritas 抽取高诊断价值知识节点，通过分层追问判断用户是否真正理解，并生成引用用户原话的诊断报告。

核心价值：
- 材料驱动：诊断对象只来自用户上传材料。
- 系统主动：用户不需要自己出题，系统主动开始诊断。
- 分层追问：所有知识节点统一按记忆→理解→应用→分析推进。
- 有据可查：报告引用用户原话，指出具体盲点。

## 2. 目标用户

已完成材料学习、需要验证理解深度的人。
典型场景：面试备考、考试复习、资格认证。

## 3. 核心流程

上传材料  
→ Agent 1 抽取 1–8 个高诊断价值知识节点  
→ Agent 2 逐节点进行四层诊断：记忆→理解→应用→分析  
→ Agent 3 生成诊断报告

## 4. 输入与材料边界

当前支持上传格式：PDF、DOCX、PPTX、TXT、Markdown

材料边界：
- 诊断只考材料中出现或明确暗示的概念，不引入材料以外的知识点作为考察对象。
- Agent 可以用通用知识判断用户回答是否正确，也可以构造类比或场景辅助追问，但考察对象始终限于材料内容。

## 5. 知识节点

Agent 1（节点分析师）从材料抽取最值得诊断的知识节点，不做泛泛总结。

输入：材料可读文本
输出：1–8 个知识节点，每个节点包含：稳定 id、节点名称、一句话说明、材料证据片段、优先级理由

优先选择：
- 核心概念和定义
- 容易混淆的对比点
- 能迁移到场景应用的问题
- 容易暴露推理断点的机制或因果链

避免选择：
- 纯背景描述
- 无法追问的孤立事实
- 诊断价值低的细节

节点规则：
- 1–8 个，按诊断价值降序排序，宁少勿滥；材料少就少抽，不凑数。
- 每个节点都要能支撑记忆、理解、应用、分析四层追问。
- 每个节点是独立诊断单元。
- 用户可选择任意节点开始；界面引导从上到下进行，因为越靠前诊断价值越高。
- 若材料过于单薄、抽不出有效节点，提示用户补充或更换材料，不强行开始诊断。

## 6. 认知层级与推进

| 层级 | 通过标准 |
|------|----------|
| 记忆 | 能识别概念或说出基本定义 |
| 理解 | 能用自己的话解释，不只是复述原文 |
| 应用 | 能把概念放进具体场景并说明怎么用 |
| 分析 | 能拆出机制、因果、边界或对比关系 |

不算通过：只堆关键词、答非所问、逻辑矛盾、场景应用和概念无关、看答案后才答对。

每个节点固定走四层：记忆→理解→应用→分析，四层全部完成后进入下一节点。

层级是唯一推进依据，不设固定轮次：通过当前层级才进入下一层；未通过就继续围绕当前层级对话，不为走完层级强行推进。只有用户在回答当前知识问题时，Agent 2 才判断当前层级是否通过；如果用户说了别的，也需要正常回应，再自然拉回当前知识点。

## 7. 提示、答案与评分

界面常驻两个按钮：给我提示 / 给我答案

- 给我提示：提供切入点、思考方向、线索或类比，不直接替用户回答。使用提示后答对，仍算通过。
- 给我答案：给出当前问题的完整答案，将当前层级标记为“答案辅助”后进入下一层，该层不算独立通过。

提示和答案的使用记录只由用户点击按钮触发，由代码记录；Agent 在对话中主动给的类比或思路不计入提示使用。报告记录提示和答案的使用情况。设计上鼓励使用提示，不鼓励直接看答案。

评分：分数是辅助摘要，不是核心结论；核心是层级通过情况、盲点证据和下一步建议。

每个节点独立计分，满分 100，四层各 25 分：
- 独立通过：25 分
- 提示后通过：25 分（提示不扣分，只在报告标注用过提示）
- 答案辅助：0 分，并在报告中标记

## 8. 对话与诊断

Agent 2（知识检验家教）逐节点完成分层诊断。

输入：当前节点、材料证据、当前层级、对话历史、用户回答
输出：自然对话回复 + 结构化状态

结构化状态包含：
- 当前层级是否通过（语义判断）
- 当前盲点摘要

下一步动作（继续当前层 / 进入下一层 / 完成节点）和提示、答案的使用记录属于确定性状态，由代码维护，不由 Agent 2 上报。

定位：一个像真人一样对话的家教，任务是检验用户是否真正理解当前知识点。用户理解了知识点就真诚鼓励，没理解就帮助和引导他，可以通过追问、反馈、换角度、给类比等方法。

对话原则：
- 主线永远是知识检验，不主动开辟闲聊、情绪、产品体验等支线。
- 用户难免说题外话（闲聊、想被夸、吐槽、走神等），需要像朋友一般自然承接几句，再把话题拉回当前知识点。既不无视，也不扯远。
- 只在用户真的在回答当前知识问题时，才判断该层是否通过。
- 怎么说话有充分自由，只受"完成当前节点知识检验"这个目标约束：可以自由地夸、自由地举例、自由地接话，但始终服务于这个目标。
- 像人一样靠常识灵活应对，不照脚本走、不套固定话术、不为每种情况预设台词或禁令。不把结构化状态播报给用户。

## 9. 诊断报告

Agent 3（报告生成器）在所有节点完成后自动生成诊断报告，不提前生成。报告生成后对话仍可继续，但不需要更新报告。

输入：所有节点的对话、层级状态、提示/答案记录、用户原话、材料证据
输出：个人化诊断报告

报告顶部：
- 各节点得分（每节点满分 100）
- 各层级通过情况
- 主要盲点摘要

每个节点：
- 层级通过情况
- 用户原话证据（引用真实原话，不编造）
- 具体盲点
- 是否使用提示、答案
- 正确理解
- 下一步建议

展示规则：节点条目默认折叠，优先展开最需要关注的 1-2 个。

语气要求：具体、直接、可执行。说清楚用户卡在哪里，不说"需要加强理解"这类空话。

## 10. 主界面

核心界面是四栏诊断工作台：
[ 左侧工作区 ] [ 知识点栏 ] [ 对话区 ] [ 右侧诊断旁注栏 ]

左侧工作区
- 新建诊断、本地历史、本地报告、设置入口
- 显示诊断记录，不显示记录下的知识点
- 一条上传材料对应一条诊断记录
- 诊断记录提供三点菜单：置顶 / 取消置顶、重命名、分享（置灰）、删除

知识点栏：
- 上传材料解析后自动填充，节点按诊断价值降序排列，越靠上越优先
- 点击节点切换到该节点的独立对话
- 知识点行提供三点菜单：置顶 / 取消置顶、重命名、分享（置灰）、删除

对话区
- 只承载当前对话，不塞进度和报告信息
- 上传解析完成后 Agent 先发轻量诊断计划（知识点数量、建议顺序），再衔接第一个问题
- 底部提供：输入框、语音输入、给我提示、给我答案

右侧诊断旁注栏
- 当前分数、当前知识节点、知识节点列表、当前层级
- 层级状态：已通过、进行中、未通过、答案辅助、未开始
- 看过答案后继续推进标记为答案辅助，不算独立通过也不算未通过
- 只放当前决策需要的信息，不做信息堆叠

## 11. 本地保存

当前阶段只做本地保存。

保存内容：
- 本地诊断历史
- 知识节点
- 对话记录
- 层级状态
- 诊断报告

实现可以从 localStorage 或 IndexedDB 起步。由于单条诊断包含材料文本、节点、独立对话、层级状态和报告，优先考虑 IndexedDB。用户应知道这些数据只保存在当前浏览器。持久化结构应有 schema 版本和迁移入口；只保存跨会话需要恢复的诊断状态，不保存错误提示、进行中请求或当前 Agent 临时响应等运行态字段。

## 12. 成功标准

一次完整诊断应该做到：
- 对话像和家教真实交流，而不是机械考试；用户卡住时系统会换角度引导。
- 报告引用用户原话，指出具体盲点；分数能看，但不盖过诊断证据。

如果用户看完报告后能明确知道"我到底哪里没懂、下一步该做什么"，Veritas 就完成了核心任务。
