## BC-A2-001：首问与记忆层目标不一致

- 案例：S01、S03、S04、S05、S07、S08、S10、S11、S12、S13、S14、S16、S17、S18、S19。
- 实际表现：后台仍是 MEMORY，问题却要求做场景选择、解释因果、分析限制因素或说明学习目标。
- 例子：S18 的记忆目标是叙述光合作用定义和物质/能量转化，首问却要求分析“光照充足、温度偏低时继续加光是否有效”。
- 为什么不符合：四层顺序存在，但题目没有按当前层检验，最终“记忆层通过”不再代表记忆证据。
- 根因：`CREATE_FIRST_QUESTION` 的 Prompt 只要求“有意义的问题”，没有强制使用 `bloomTargets.memory`；代码随后把这道题固定放入 MEMORY。
- 解决：首问操作显式声明当前层为 MEMORY，并要求问题只检验 `bloomTargets.memory`；把首问层级对齐加入结构化评测，而不是关键词规则。
- 回归：同一材料至少连续 3 次；人工逐题对照 memory target，目标 90% 以上完全对齐，任何应用/分析题进入 MEMORY 均失败。

## BC-A2-002：同一轮出现两道主问题

- 案例：S01、S02、S11、S14、S15、S20，共确认 9 次。
- 实际表现：正确反馈中的 `assistantMessage` 已经提出下一道问题，代码又追加 `CREATE_STAGE_QUESTION` 生成的正式问题；两题有时考察方向不同。
- 为什么不符合：用户不知道该回答哪一道，也破坏“每轮只推进一件事”和“每层唯一主问题”。
- 根因：Prompt 没说明正确通过时 `assistantMessage` 只能反馈和自然过渡、不得发起新诊断题；状态代码无条件再生成下一层主问题。
- 解决：把“评价反馈”和“下一层主问题”职责彻底分开；正确通过的评价 schema/Prompt 明确禁止承担下一题，下一题只来自唯一问题操作。
- 回归：所有正确推进案例检查新增消息；允许反馈 + 一道主问题，但反馈本身不能再要求用户完成另一个回答动作。

## BC-A2-003：连续无进展阈值失效

- 案例：S12。
- 实际表现：三次“不知道”均得到新支架，但 MEMORY 的 `stalledCount` 三次都为 0；没有自动完整讲解。
- 为什么不符合：设计明确要求连续三轮 `STALLED` 后自动答案并进入 `PASSED_WITH_ANSWER`。
- 根因：Agent 2 把“不知道”处理成普通对话/支架，没有返回诊断评价事件；不是 reducer 计数错误。
- 解决：当前有主问题且用户无法作答时，语义上仍属于该题的 `NO_ANSWER`，同时可返回 scaffold；`NO_ANSWER + STALLED` 必须进入 reducer。
- 回归：使用至少 6 种不知道、含糊和无答案表达，连续三轮与中途产生新理解两类路径都要覆盖。

## BC-A2-004：照抄分类失效

- 案例：S13。
- 实际表现：用户逐字复述材料，Vita表扬“准确复述、基础扎实”，只按缺失点继续追问，没有要求改用自己的话。
- 为什么不符合：产品明确区分 `COPIED`，理解不能只由原文复述证明。
- 根因：Agent 2 没有把用户文本与当前材料做语义重合判断，分类落在普通不完整回答。
- 解决：Prompt 要求比较用户回答与已提供材料；高度复述且缺少自主解释时使用 `COPIED`，反馈给出新的表达角度，不用禁词或单一字符串相似度替代语义判断。
- 回归：逐字复制、轻微改写、正确自主解释、合理引用原文四类对照案例。

## BC-CTX-001：学习目标只在当轮生效，没有保存

- 案例：S14。
- 实际表现：Vita明确说已理解业务考试目标，后续题目也使用该信息，但 IndexedDB 中 `learningGoal` 仍为空。
- 为什么不符合：目标应是持续上下文；刷新、长对话裁剪或主题切换后不能只依赖最近消息碰巧存在。
- 根因：Agent 2 没有在明确目标消息中返回 `learningGoalUpdate`，代码因此没有持久化。
- 解决：明确表达或改变稳定学习目标时必须返回结构化目标更新；代码继续只保存通过 schema 的值。
- 回归：新增目标、补充目标、改变目标、只是讨论某类考试但并非个人目标四类语义案例，并验证刷新后恢复。

## BC-A2-005：暂停请求执行不完整

- 案例：S05。
- 实际表现：Vita完整讲解且没有评分，但用户说“暂时不要追问”后仍以“需要我再展开哪一块？”结尾；讲解还加入材料之外的 90% 持仓、一级市场申赎和费用结论，未说明是扩展知识。
- 为什么不符合：用户明确要求当前轮不追问；扩展内容应标明与材料的边界。
- 根因：通用回答风格仍有默认追问习惯，对材料内事实与通用知识的边界表达不足。
- 解决：尊重显式的交互偏好；该轮以完整回答结束。允许外部知识，但需在内容会影响结论时说明“材料未展开，下面是一般性补充”。
- 回归：暂停考试、只讲不问、只要结论、欢迎追问四种偏好对照。

## BC-A3-001：报告盲点超出证据

- 案例：S20。
- 实际表现：报告把“现金仓位、双重费用、申赎调整”列为用户尚未推导的盲点，但材料、问题和用户回答均没有检验这些内容。
- 为什么不符合：未被诊断的细节不能被描述成用户盲点；这会损害报告可信度。
- 根因：`blindSpots[]` 是无证据 ID 的自由文本，代码只能检查报告结构，不能验证该盲点是否来自某一道题或材料来源。
- 解决：为每条盲点增加证据类型和 ID，只允许引用已提出的问题、真实用户回答或当前节点来源；代码验证 ID 存在和角色，模型判断语义相关性。
- 回归：混合普通请求、提示、答案、正确回答和未被提问的材料细节，要求报告只写被真实暴露的盲点。

## BC-RPT-001：Markdown 暴露内部枚举

- 案例：S01—S20，20 / 20。
- 实际表现：网页报告显示“独立通过、提示后通过、依赖完整答案”，下载 Markdown 却显示 `PASSED`、`PASSED_WITH_HINT`、`PASSED_WITH_ANSWER`。
- 为什么不符合：下载报告也是用户可见产物，设计明确禁止内部枚举。
- 根因：确定性 `reportToMarkdown` 直接输出存储状态，没有使用中文映射。
- 解决：在 Markdown 渲染层使用与网页一致的中文状态映射；内部 document 继续保存枚举，不改变状态事实。
- 回归：三种状态各生成一份报告，检查页面与 Markdown 语义一致且不含内部词。

## 观察项，不计为正式 Badcase

- 同一 ETF 材料重复运行时主题数出现 1 或 2；同一城市内涝材料出现 1 或 2。所有核心条目唯一归属、来源和报告进度均合法，尚无足够证据证明存在覆盖遗漏，因此先列为 Agent 1 结构稳定性观察项。
- S03 的预设回答没有适配随机首问，导致连续偏题。Vita没有错误放行，不能把 0 分归因于模型判断；该案例只支持“首问层级偏高”的结论。
