# Veritas 任务 1—4 前后版本 120 Session 对比协议

## 固定版本

- 迭代前：`f48d2b00e53954035bce27297a426a1ea20957f0`
- 迭代后：`7bc997f04f19eb5c9b9a22d308abfb999bb96d1d`
- 版本关系：迭代前 → 任务 1 → 任务 2 → 任务 3+4 → 迭代后；中间没有其他产品提交。
- 模型：两个版本统一使用 `deepseek-v4-flash`。
- 评测执行器 SHA-256：`B808FC4B28688EE95836984C77F8FB8A099AC943187083F14CB41F95B86C2A13`。

## 样本与轮次

- 沿用 `a0691c1` 的 S01—S20，共 20 个 Case。
- 每个版本独立运行 3 轮，每轮 20 个 Session，共 120 个正式 Session。
- 各轮材料、用户输入、动作顺序和判断标准保持一致。
- 第 1 轮顺序：迭代前 → 迭代后。
- 第 2 轮顺序：迭代后 → 迭代前。
- 第 3 轮顺序：迭代前 → 迭代后。三轮为奇数，这是不增加额外实验设计时最接近平衡的顺序。
- 用户未来输入只保存在 Playwright 执行器中，每一轮只把当前已发生的消息发送给产品；模型无法读取未来答案。

## 正式链路

每个 Session 均经过：Microsoft Edge 1440×900 → 文件上传 → 正式生产构建 → `/api/agents` → 真实 DeepSeek → IndexedDB → Agent 3 报告。

- 不使用 Mock、内部函数直调、直接 API 造状态或人工写入 IndexedDB。
- `setInputFiles` 只替代操作系统文件选择窗口，材料仍进入真实解析和 Agent 1 链路。
- 目标交互结束后的自动“看答案”仅用于完成四层并生成报告，证据中单独标记为“自动补全”，不算用户自主掌握。
- 每个 Session 保存原始 JSON、目标阶段截图、报告 Markdown、报告截图和最终状态。

## 失败与重试

- 模型回答不理想、产品 Bug 或随机波动不得通过重跑后择优替换。
- 页面出现真实“重试本轮”时，执行器最多按真实用户路径重试 4 次，并完整记录失败请求和重试。
- 测试框架、浏览器或基础设施故障必须单独归档；只补跑受影响且未形成有效 Session 的 Case，不与产品结果混算。
- 任一正式 Session 的原始证据一经形成不得覆盖。

## 指标

客观指标优先于主观总分：

1. 首问—记忆层目标匹配率，分母按实际出现该判断机会的 Session 计算；
2. 不完整回答错误放行率；
3. 正确回答后重复或双正式问题率；
4. 连续“不会/不知道”的有效累计与三次自动答案成功率；
5. 普通对话、暂停、安全请求等非回答消息的误评分或状态污染率；
6. 提示、答案、刷新、多主题、报告等关键流程异常率；
7. Agent HTTP 非 200、用户侧重试与执行失败频率；
8. PASS / PARTIAL / FAIL 的三轮平均表现；
9. 20 个 Case 的稳定性：`3/3 PASS`、`3/3 PARTIAL`、`3/3 FAIL`、三轮结果不一致。

最终分析同时记录新版改善、未改善和可能退化的指标，不筛选对新版有利的数据。
