# 修复前后量化对照

旧版来源为 `docs/evaluation/a0691c1/` 的同一组 S01—S20。新版沿用相同材料和用户输入，但问题由真实模型动态生成，因此按语义目标比较，不假定两次问题文本相同。

## 总体结果

| 指标             |         修复前 |          修复后 |         变化 |
| ---------------- | -------------: | --------------: | -----------: |
| PASS             | 12 / 20（60%） |  13 / 20（65%） |  +5 个百分点 |
| PARTIAL          |  5 / 20（25%） |   7 / 20（35%） | +10 个百分点 |
| FAIL             |  3 / 20（15%） |    0 / 20（0%） | -15 个百分点 |
| 非 FAIL          | 17 / 20（85%） | 20 / 20（100%） | +15 个百分点 |
| 平均评测分       |       3.85 / 5 |        4.00 / 5 |        +0.15 |
| 技术链路最终完成 |        20 / 20 |         20 / 20 |         持平 |
| 无用户侧重试完成 |        20 / 20 |         19 / 20 |  -5 个百分点 |

PARTIAL 增加不是单纯退化：旧版 3 个明确 FAIL 已全部退出 FAIL；同时本轮严格把动态题失配和真实 502 记为 PARTIAL，没有用“最终跑完”掩盖不确定性。

时延和 502 受真实上游波动影响，单次 20-session 不能证明代码导致性能变化。它们应作为发布稳定性风险，而不是简历中的“性能提升”。

## 可以写进简历的量化表述

推荐版本：

> 设计并落地 Veritas 多 Agent 学习产品的 20-session 端到端回归体系，覆盖真实 Edge、生产构建、256 次模型调用、四层状态机与报告证据；基于 bad case 回流迭代 Agent 2 Prompt/结构化契约，将首问—记忆层对齐率从 25% 提升至 100%，消除原评测中 2 个明确错误推进案例，使 17 次非正确判定保持 0 次误推进，并将连续无回答状态识别从 0/3 提升至 3/3；双问题由 9 次降至 2 次（-77.8%），版本级 FAIL 率由 15% 降至 0%。

更短版本：

> 构建 20-session 真实链路 Agent 回归集与结构化 bad case 闭环，推动四层诊断逻辑迭代：首问层级对齐率 25%→100%，双问题 -77.8%，明确错误推进案例 2→0，FAIL 率 15%→0%。

## 不应写进简历的说法

- “20 个案例全部通过”：产品判定实际为 13 PASS、7 PARTIAL。
- “彻底解决双问题”：仍有 2 次。
- “系统稳定性提升到 100%”：本轮有 1 次 502 和 1 次用户侧重试。
- “COPIED 检测已修复”：S13 本轮没有真正覆盖该语义。
- “Agent 3 报告幻觉已解决”：S20 改善，但 S03/S09/S14/S15 仍有报告语义问题。
- “线上用户数据/A-B 实验”：这是本地正式构建的真实模型回归，不是线上流量实验。
