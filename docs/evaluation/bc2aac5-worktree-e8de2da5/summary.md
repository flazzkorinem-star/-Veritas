# 真实回归结论

## 结论

这四个部分确实构成产品更新与迭代，而且真实回归证明了核心诊断稳定性有提升：首问层级、非完整回答推进、连续无回答和学习目标持久化均有明确正向证据。最强的量化结果是首问—MEMORY 对齐率从 25% 提升到 100%，原评测中的明确错误推进案例从 2 个降为 0，S12 的有效停滞识别从 0 / 3 提升到 3 / 3。

但任务 3 还不能宣布完成：双问题从 9 次降到 2 次，是 77.8% 的改善，不是清零。回归还暴露了 S18 状态污染、S09 502、报告语义可信度和 Markdown 枚举泄漏。因此可以写成“基于评测驱动的产品迭代”，不能写成“20 条全面通过”或“稳定性达到 100%”。

## 量化概览

- 20 / 20 个真实 session 最终完成；19 / 20 无需用户侧重试。
- 256 次 Agent API 操作：255 次 200、1 次 502。
- 45 个目标交互后，提示和答案按钮保留率 100%。
- 7 个被正确识别为普通对话的回合，诊断状态保持率 100%。
- 17 次非 CORRECT 诊断判断，错误推进 0 次。
- 29 / 29 个结构化用户引用合法，14 / 14 个 Markdown 引文逐字真实。
- 产品评分：13 PASS、7 PARTIAL、0 FAIL，平均 4.00 / 5。
- 相比旧版：PASS 60%→65%，FAIL 15%→0%，非 FAIL 85%→100%。

## Agent 1：4 / 5

- 20 / 20 材料完成真实提取和知识地图审计；所有结构通过 schema 和确定性保存。
- S14 能把考试代码识别作为有效核心知识，S18 把提示注入材料归为参考而非诊断目标。
- 主要问题是粒度随机性：15 个高度相似 ETF session 中，14 个生成 1 个主题，S08 生成 3 个主题；相同材料的学习工作量不稳定。

## Agent 2：4 / 5

- 任务 1、2、4 的关键真实路径通过，通用对话、提示、答案、多主题恢复和刷新恢复保持可用。
- 20 / 20 首问与 MEMORY 目标对齐；17 / 17 非正确判断没有错误推进。
- 仍有 2 次正确反馈自行提问，说明 Prompt 约束不足以确保唯一正式题。
- S18 把安全请求当作 NO_ANSWER 并累计停滞，违背“只有确实回答问题时才评分和推进”的产品定义。
- S13 没有有效覆盖 COPIED，暂不能为复制检测背书。

## Agent 3：3 / 5

- 所有报告完成；用户消息 ID 和 Markdown 引文的事实存在性校验有效。
- S20 没有复现旧版无证据“现金仓位/双重费用”等盲点，S12 能明确写出用户没有独立掌握。
- 仍存在“只看了答案却写已理解”、把材料外绝对结论当盲点、摘要与 understood 数组冲突等语义问题。
- 20 / 20 Markdown 下载仍泄漏内部枚举，报告还未达到可放心分享的产品标准。

## 最优先的三项下一版工作

1. **把唯一正式问题变成确定性接口。** 不再只依赖 Prompt 禁止问句；正确反馈与下一题应在结构和渲染层彻底分权，发布门槛为双题 0 次。
2. **修正“消息意图 → 状态事件”的语义边界。** 请求、拒绝、流程沟通不能变成 NO_ANSWER；同时新增问题条件化 COPIED 真实 case，避免状态机正确执行错误事件。
3. **收紧报告语义和下载模板。** 在合法 ID 之外验证结论与证据的蕴含关系、已验证/仅讲解边界和已诊断范围；同时用确定性映射消除 20 / 20 Markdown 枚举泄漏。

S09 的 502 应作为独立发布可靠性门槛持续监控：下一版至少重复运行高风险 case，区分上游偶发失败、结构化输出失败和客户端恢复体验。

## 本轮盲区

- 每个 case 只运行一次，无法给出统计置信区间；相同 ETF 材料的多次出现不是同一 case 的重复实验。
- S13 没有真正触发 COPIED。
- 固定回答无法适配所有动态问题，S01/S02/S03 的后半程不能用来断言四层正确回答稳定率。
- 最长目标对话为 5 个动作；没有数十轮长对话、跨日恢复或大量主题。
- 材料以短 Markdown 为主，没有充分覆盖复杂 PDF、扫描件、表格、长文和低质量材料。
- 没有覆盖移动端、语音输入、打印/PDF 分享、系统文件选择器和真实人工操作速度。
- 所有最终报告都经过自动点击答案补全，不能当作自然完成率。
- 没有线上真实用户、并发、弱网、限流或长期监控数据。

## 最终判断

可以把本轮写进简历，最准确的能力标签是：**评测体系构建、真实链路回归、bad case 归因、Prompt/状态契约迭代、量化验证与诚实的发布判断**。这比只写“优化 Prompt”更能体现产品迭代能力，也比声称“全部修复”更经得住面试追问。
