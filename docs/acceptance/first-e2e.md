# 首条端到端验收基线

## 验收材料

使用 `tests/fixtures/end-to-end/water-cycle.md`。它包含自然水循环、城市化影响和海绵城市措施三个来源明确的模块，覆盖定义、机制、应用、边界和常见误解，足以检验完整知识地图与四层教学。

## 预期知识覆盖

- 三个材料模块均被保留，并能追溯到对应标题或段落。
- 核心内容至少覆盖：水循环环节、太阳能与重力的作用、不透水表面对下渗和径流的影响、城市内涝的多因素成因、海绵设施的作用机制与容量边界。
- 每个核心知识条目只归入一个主要诊断主题；辅助例子必须绑定主题或说明仅作参考的理由。
- 不限制主题总数，但不得遗漏上述核心内容，也不得把互不相干的概念为减少数量强行合并。

## 首条真实流程

1. 在空主界面的输入区上传该 Markdown 文件，立即创建本地任务。
2. 显示真实文件读取进度；模型阶段只显示阶段名称、不定进度和已用时间。
3. Agent 1 完成分块提取、全局整理和覆盖审计，所有结构化输出通过 Zod。
4. 自动打开排序第一的主题，由 Agent 2 判断材料质量和学习价值，给出一个非模板化的自然开场，不默认出题。
5. 先验证普通提问能获得完整回答且不改变分数，再由用户明确要求检验理解；依次通过直接答对、使用提示后答对和查看答案等路径走完至少一个主题的四层，代码计算分数和状态。
6. 切换主题并返回后，原问题、消息、草稿、提示状态和分数保持不变；刷新页面后任务可恢复。
7. 完成一个主题后，Agent 3 生成任务级报告，忠实区分已诊断、未诊断、辅助覆盖和仅作参考内容。
8. 从“进度”入口打开报告；报告可在网页查看、下载 Markdown，并通过系统分享或复制回退导出摘要。

## 自动化断言

- 上传到自然主题开场、通用对话，再到用户按需启动首个真实问题的纵向链路无生产 Mock。
- 普通消息不会启动四层、显示提示与答案入口或改变诊断状态；用户明确要求检验后才进入诊断。
- 材料进度只按完成主题数计算；当前主题分数只按四层的 `25/25/25/25` 或 `0` 规则累计。
- 模型文本不能直接修改层级、分数、任务完成或持久化状态。
- 用户明确说不知道后，家教必须针对当前问题提供具体支架；请求提示时，返回的提示级别必须与当前点击一致。
- 整份处理不超过 5 分钟，Agent 1 模型阶段不超过 3 分钟；达到上限后停止当前请求并进入可重试状态。
- 模型请求进行中点击取消后立即停止等待并允许重新处理；处理中刷新页面后显示明确的中断原因，不继续伪装为处理中。
- 页面与报告不出现固定禁用话术，不显示内部阶段枚举、“确定性分数”、系统提示词、推理内容、原始上游错误或秘密。
- 1440×900 与 390×844 均可完成主流程，无横向溢出、严重控制台错误或失败网络请求。

## 阶段性使用方式

- 阶段 5：验证 Markdown 上传至自然主题开场。
- 阶段 7：验证四层、提示、答案、无进展与主题恢复。
- 阶段 9：验证报告、下载与分享。
- 阶段 11：验证 390×844 完整流程。
- 阶段 13：在本地生产构建中执行完整 Mock 验收。
- 阶段 14：在同一个生产 Edge 任务中用真实 DeepSeek 连续完成上传、诊断教学、主题完成与报告，不以拆分 API 冒烟替代。
