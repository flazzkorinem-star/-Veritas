# 完整知识地图与分批深度诊断

## Problem Statement

如何让希望确认自己真正学会材料的用户看见整份材料的学习范围，并最终完成可靠诊断，同时不强迫他一次经历几十个知识点乘以四层的漫长问答？

## Recommended Direction

Agent 1 先按材料结构提取完整、可追溯的知识地图，再区分核心诊断知识与辅助内容，把 2—5 个高度相关且可以共享四层目标的核心条目聚合为一个诊断主题。产品不再设置“整份材料最多 8 个节点”之类的总量硬上限，也不把抽样包装成完整覆盖。

用户每次只被建议完成一个诊断主题。所有主题按材料模块折叠展示并支持跨节点切换；节点完成后由用户决定暂停或继续。任务和报告始终明确区分已诊断、尚未诊断、绑定为辅助内容和仅作参考的条目。

## Key Assumptions to Validate

- [ ] 用户愿意把完整材料诊断分多次完成，而不是要求一次结束；通过可恢复历史、完成反馈和真实使用观察验证。
- [ ] 2—5 个高度相关条目可以共享一个四层诊断主题而不牺牲诊断清晰度；通过真实材料与人工检查验证。
- [ ] 完整知识地图能显著降低用户对“系统是不是漏了内容”的不安；通过可用性访谈和任务完成后的主观反馈验证。
- [ ] 一次完成一个四层主题仍然不会产生明显考试感；通过对话体验测试验证。

## MVP Scope

- 分块提取材料模块和原子知识条目；
- 区分核心知识与辅助内容；
- 全局合并、去重、聚合诊断主题和覆盖审计；
- 每个条目必须拥有明确的覆盖归属；
- 模块化节点列表、已完成与尚未诊断数量；
- 每个诊断节点固定走记忆、理解、应用、分析四层；
- 一次建议完成一个节点，结束后由用户选择暂停或继续；
- 任务级报告明确展示覆盖情况。

## Not Doing

- 不设置总节点上限 8——它会把体验长度问题伪装成内容覆盖问题；
- 不让每条案例、数据和辅助事实单独经历四层——这会制造无意义的对话爆炸；
- 不让用户手工修正、合并或拆分节点——抽取质量由产品协议和后续评测负责；
- 不建立复杂知识图谱或跨节点能力推断——首版只保留模块、来源与有限前置排序；
- 不把尚未诊断的内容标记为已掌握。

## Resolved Decisions

- 学习目标已经确定为内部自动建立；没有确认 UI 和固定选项，用户只在对话中自然表达调整。
- 主界面保留材料主题完成进度与当前主题 0—100 分，不默认展示四层术语和额外节点完成卡片。
- 真实材料中“相关到可以聚合”的边界留待稳定版本后的 benchmark 持续校准，不阻塞首版。
